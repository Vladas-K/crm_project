# Event Agency CRM

Внутренняя CRM для event-агентства на Django. Система объединяет продажи и операционную работу в одном процессе:

```text
лиды → воронка → клиенты → мероприятия → задачи / расходы / подрядчики / документы / коммуникации → аналитика
```

Проект находится в активной разработке и сейчас предназначен для локального использования и проверки продуктовых сценариев.

## Что уже реализовано

### Продажи и клиенты

- дашборд с рабочими показателями и блоком «Требует внимания»;
- лиды с источником, этапом, вероятностью, ответственным менеджером и причиной отказа;
- автоматическое назначение нового лида менеджеру по продажам с наименьшей нагрузкой;
- контроль лидов без первого контакта более 24 часов;
- воронка продаж с управляемыми этапами;
- карточки B2B/B2C-клиентов, сегментация и LTV;
- поиск, фильтры и autocomplete для лидов и клиентов.

### Мероприятия

- список мероприятий с поиском, фильтрами по статусу, формату, датам и проблемным состояниям;
- операционная карточка мероприятия с финансовой сводкой и контрольными показателями;
- вкладки задач, тайминга, рисков, итогов, расходов, подрядчиков, коммуникаций и документов;
- создание и редактирование связанных записей непосредственно из карточки мероприятия;
- быстрые действия для статусов задач и подрядчиков;
- отдельный раздел задач с фильтрами и детальными карточками;
- календарь мероприятий.

### Шаблоны и справочники

- форматы мероприятий с шаблонами задач, тайминга, бюджета и рекомендуемых подрядчиков;
- явное применение шаблона формата к мероприятию без дублирования уже созданной структуры;
- пакеты услуг;
- управляемые категории расходов;
- управляемый справочник ролей подрядчиков.

### Подрядчики

- отдельная карточка каждого подрядчика;
- специализации и поддерживаемые форматы мероприятий;
- рейтинг, надёжность, диапазон стоимости и история назначений;
- структурированные контакты: контактное лицо, должность, телефон, email и сайт;
- отдельные каналы Telegram, WhatsApp, MAX, Instagram и ВКонтакте;
- регион работы, предпочтительный способ связи, занятость и ссылки на портфолио;
- нормализация российского телефона из `8…` в `+7…` и автоматическое добавление `https://` к сайту;
- отдельная форма создания и редактирования с тематическими разделами и компактным множественным выбором.

### Доступ и интерфейс

- стандартная Django-аутентификация через `/accounts/login/`;
- CRM-профиль сотрудника с ролью и отдельными флагами доступа;
- разграничение просмотра финансов, клиентов и аналитики;
- отдельные разрешения на управление лидами, клиентами, мероприятиями и системными справочниками;
- скрытие недоступных разделов, финансовых данных и действий в интерфейсе;
- светлый адаптивный интерфейс на Django Templates и Bootstrap 5.

## Права доступа

Права хранятся в `TeamMemberProfile` и настраиваются через Django admin:

| Флаг | Назначение |
| --- | --- |
| `can_view_finance` | Бюджеты, расходы, оплаты, прибыль и финансовая аналитика |
| `can_view_clients` | Просмотр клиентов |
| `can_view_analytics` | Доступ к аналитике |
| `can_manage_leads` | Создание и редактирование лидов |
| `can_manage_clients` | Создание и редактирование клиентов |
| `can_manage_events` | Управление мероприятиями и связанными рабочими данными |
| `can_manage_system` | Управление справочниками, пользователями и удаление основных записей |

Запросы без необходимого права получают ответ `403`. Финансовые значения и недоступные действия дополнительно скрываются в шаблонах.

## Установка и запуск

```bash
git clone https://github.com/Vladas-K/crm_project.git
cd crm_project

python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

python manage.py migrate
python manage.py load_demo_data
python manage.py runserver
```

После запуска CRM доступна по адресу <http://127.0.0.1:8000/>. Неавторизованный пользователь будет перенаправлен на страницу входа.

## Особенности локальной разработки

- используется SQLite, файл `db.sqlite3` не отслеживается Git;
- загруженные файлы из `media/` также исключены из репозитория;
- данные текущей локальной базы являются тестовыми, поэтому при изменении схемы допускается пересоздание базы и повторный запуск `load_demo_data`;
- медиафайлы обслуживаются Django только при `DEBUG=True`;
- текущие настройки предназначены для разработки, отдельной production-конфигурации пока нет.
